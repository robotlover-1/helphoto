# AI 摄影指导 App — 设计文档

- 日期：2026-10-19
- 状态：已评审，待用户批准后进入实现计划
- 主题：面向大众用户的拍照 + AI 调色建议 + 风格迁移 App

## 1. 概述

一款移动端 App：用户拍照（或从相册选图），用自然语言描述想要的风格（如"日系清新"），App 用 AI 分析照片并给出**通俗语言的调色建议 + 具体参数**，把这些参数预设到 App 内的滑块上，用户手动微调到满意后导出。同时支持导入一张**风格参考图**，分析其调色参数并套用到自己的照片上；不满意时可继续给反馈，进入迭代循环。

产品定位是"AI 摄影指导"，而非"一键自动修图"：AI 给出建议和起始参数，最终效果由用户手动控制。

## 2. 背景与约束

- **开发机是 Linux**：无法进行 iOS 原生开发（Xcode/Core Image 仅 macOS）。iOS 最终安装包需一台 Mac 才能打包，但代码可提前写好。
- **目标用户**：大众用户（摄影小白），建议必须用通俗语言，参数术语可作参考。
- **交互模型**：App 内置滑块，AI 预设建议值，用户在此基础上微调（自动调整可能达不到用户预期，因此不追求"一键出片"）。
- **开发分工**：代码由 Claude（本文档作者）编写，用户负责提供想法、建议与指导。
- **技术选型原则**：在 Linux 可开发的约束下追求"效果最好"。

## 3. 范围

### v1（本版交付）

- 流程 A：拍照/选图 → 输入想法 → AI 建议（参数 + 通俗解释）→ 预设滑块 → 微调 → 导出。
- 流程 B：导入风格参考图 + 自己的照片 → AI 分析风格 → 参数迁移 → 预设滑块 → 微调 / 迭代。
- 8 个调色参数（见第 5 节），自定义 shader 实时预览 + 导出。
- 迭代循环（"继续给建议"）。

### v1 之外（推迟到 v2，本版明确不做）

- 视频分析（剪辑手法 + 调色参数）。
- 非线性的 HSL（按色相调色）与色调曲线。
- 相机取景器的实时滤镜叠加（v1 是"拍照后编辑静止图"）。
- 原始分辨率导出（v1 统一最长边 2048px）。
- 账号体系、云同步、商业化（付费/订阅）。

## 4. 总体架构

分**前端 App（Flutter）+ 后端代理（Node）**，前端内部四层：

```
photoapp/
├── app/                        # Flutter 前端
│   └── lib/
│       ├── models/
│       │   └── edit_params.dart      # ① 参数模型（不可变，含默认值/范围）
│       ├── engine/
│       │   ├── color_shader.dart     # ② 图像编辑引擎（fragment shader）
│       │   └── params_to_uniforms.dart
│       ├── ai/
│       │   ├── ai_client.dart        # ③ AI 分析层（调后端 HTTP）
│       │   ├── prompt_templates.dart
│       │   └── params_schema.dart
│       ├── screens/                  # ④ UI 层
│       │   ├── capture_screen.dart   #    拍照/选图 + 输入想法
│       │   ├── style_screen.dart     #    导入风格参考图
│       │   └── edit_screen.dart      #    编辑：预览 + 滑块 + 建议卡片
│       ├── widgets/param_slider.dart
│       └── state/                    #    Riverpod 状态管理
└── server/                     # 后端代理（Node + Express）
    ├── index.js                #    单端点：POST /analyze，持有 Claude key
    └── prompt.js               #    提示词模板 + 参数 schema
```

### 四个层次

| 层 | 职责 | 依赖 |
|---|---|---|
| ① 参数模型 | 定义有哪些参数、默认值、取值范围、中文名 | 无 |
| ② 图像引擎 | 把参数值 → shader uniform → 实时预览 + 导出成图 | ① |
| ③ AI 层 | 把「照片+想法/风格图」发给后端，拿回参数 JSON | ①（schema 一致） |
| ④ UI 层 | 页面流转、滑块、建议卡片 | ①②③ |

**关键设计**：③ 的 AI 返回 JSON 与 ① 的参数模型共用同一份 schema，保证 AI 建议能直接映射到滑块，不出现"AI 说了个参数但 App 没有对应滑块"的情况。

**后端存在的必要性**：Claude API key 不能打进 App 包（可被反编译），后端代理负责持有 key、图片降采样、JSON 校验。开发阶段在本机跑本地 Node 服务，手机连局域网访问。

**状态管理**：Riverpod。`照片`、`当前参数`、`AI 建议` 三个 provider，滑块与 AI 建议都写同一个 `editParamsProvider`，单一数据源。

## 5. 参数 Schema 与图像编辑引擎

### 5.1 参数集（v1 共 8 个）

滑块对外用整数范围 `-100 ~ +100`（默认 0），内部再转成 shader 所需值：

| 参数 | 中文名 | 作用 | 本质 |
|---|---|---|---|
| exposure | 曝光 | 整体明暗 | 乘性 `×2^EV` |
| contrast | 对比度 | 明暗反差 | 绕中灰 0.5 缩放 |
| temperature | 色温 | 冷暖（蓝↔黄） | 通道缩放 R/B |
| tint | 色调 | 绿↔品红 | 通道缩放 G |
| saturation | 饱和度 | 颜色浓淡 | 朝灰度混合 |
| vibrance | 鲜艳度 | 优先提低饱和色 | 逐像素非线性 |
| highlights | 高光 | 压/提亮部 | 逐像素非线性 |
| shadows | 阴影 | 提/压暗部 | 逐像素非线性 |

### 5.2 用自定义 shader 而非颜色矩阵

- 颜色矩阵只能做线性仿射变换，覆盖前 5 个参数（曝光/对比度/色温/色调/饱和度）。
- 高光、阴影、鲜艳度是逐像素非线性操作（依赖每个像素自身的亮度/饱和度），必须 shader。
- 采用一个 GLSL fragment shader 统一实现全部 8 个参数，uniform 由滑块驱动，60fps 实时预览，为 v2 的曲线/HSL 留扩展位。

### 5.3 预览与导出同源

- **预览**：照片作为纹理喂给 shader，实时渲染到屏幕。
- **导出**：`PictureRecorder → drawImage(shader) → toImage()`，用同一 shader 渲染到全分辨率再存相册。
- 避免"预览一套算法、导出另一套算法"导致效果不一致。

### 5.4 导出分辨率

手机照片动辄 12MP，但 Flutter GPU 纹理有尺寸上限（通常 4096 左右）。v1 导出统一缩到**最长边 2048px**；原始分辨率导出放 v2。

### 5.5 参数 → shader 的映射

`params_to_uniforms.dart` 提供纯函数 `EditParams → List<Float32List>`。纯函数便于精确单元测试。

## 6. AI 分析层

### 6.1 参数 JSON schema（与 EditParams 严格一致）

```json
{
  "params": {
    "exposure": 8, "contrast": -12, "temperature": -18, "tint": 5,
    "saturation": 10, "vibrance": 15, "highlights": -10, "shadows": 22
  },
  "explanation": "想要日系清新：整体提亮一点、降低对比度、色温偏冷、阴影微微发灰……",
  "summary": "日系清新感"
}
```

- `params`：8 个整数，`-100 ~ 100`，字段名与 App 模型对齐。
- `explanation`：通俗语言解释（面向小白）。
- `summary`：一句话概括本次调整思路。

### 6.2 三种模式

| 模式 | 输入 | 输出 |
|---|---|---|
| `intent`（A：想法建议） | 照片 + 想法文字 | 参数 + 解释 |
| `style`（B：风格迁移） | 风格参考图 + 自己的照片 | 参数 + 解释 |
| `refine`（迭代） | 照片 + 当前参数 + 用户反馈 | 新的绝对参数 + 解释 |

系统提示词统一设定角色 + 8 个参数的定义（物理含义、取值范围），三种模式都只输出同一份 JSON。

### 6.3 结构化输出

用 Claude 的结构化输出（JSON schema 约束）把 schema 作为输出约束传入，API 层面保证返回合法 JSON、字段类型与范围正确。后端再校验一次兜底。

### 6.4 后端端点与图片预处理

```
POST /analyze
{ mode, image, referenceImage?, intent?, currentParams?, feedback? }
→ { params, explanation, summary }
```

- 前端发送前把图降到**最长边 1024px、JPEG 质量 80**，转 base64。
- 模型：Claude 视觉模型（Sonnet 起步，可切 Opus 提升质量）。单次分析约 2~5 秒。

### 6.5 迭代循环

```
拍照 → 建议(第1次) → 用户微调 → 还不满意
   ↑                                    │
   └── 输入反馈 → refine(带当前参数) ────┘
```

用户点"继续给建议"并输入反馈，App 把**当前参数 + 反馈**发给后端，Claude 返回**新的绝对参数**（非增量，省去 App 做增量叠加的出错可能），滑块跳到新值，用户继续微调。可无限循环。

## 7. UI 流程与状态管理

```
流程 A（想法建议）
相机/选图 → 输入想法("日系清新") → [loading 分析] → 编辑页(预设滑块) → 微调 → 导出

流程 B（风格迁移）
导入风格参考图 → 导入自己照片 → [loading 分析] → 编辑页(预设滑块) → 微调/继续建议 → 导出
```

- **编辑页（EditScreen）为核心**，A/B 共用：顶部预览图；下方建议卡片（`summary` 标题 + `explanation` 解释）；再往下 8 个滑块，默认值 = AI 建议值。
- **继续给建议**：编辑页按钮 → 弹输入框写反馈 → `refine` 模式刷新滑块。

## 8. 错误处理

| 场景 | 处理 |
|---|---|
| 网络失败 / 后端不可达 | 错误提示 + 重试按钮 |
| API key 失效 / 额度不足 | 后端返回明确错误码，App 友好提示 |
| Claude 返回解析失败 | 结构化输出 + 后端校验兜底；仍失败重试 1 次，再失败提示重试 |
| 图片过大 | 前端强制降采样后再发 |
| shader 编译失败（罕见） | 回退到颜色矩阵（前 5 个参数仍可用） |
| 相机/相册权限被拒 | 引导去系统设置开启 |

## 9. 测试策略

1. **单元测试（纯函数）**：`params_to_uniforms` 的每个参数数学变换；JSON schema 校验器。
2. **后端测试**：mock Claude 响应，测 prompt 组装 + JSON 校验 + 重试逻辑。
3. **Widget 测试**：滑块↔参数绑定、建议卡片渲染、AI 返回后滑块跳转到正确预设值。
4. **手工真机走查**：拍照→建议→微调→导出，用真实 key 过一遍全流程。

## 10. 技术栈

- 前端：Flutter（Dart），Riverpod 状态管理，`camera` + `image_picker` 插件，fragment shader（GLSL）。
- 后端：Node.js + Express，调用 Anthropic Claude 视觉 API（结构化输出）。
- 模型：Claude Sonnet（默认），可切 Opus。

## 11. 成功标准

- 用户拍照后输入想法，能在数秒内得到通俗解释 + 预设好的 8 个滑块。
- 拖任意滑块时预览 60fps 实时更新，导出的成图与预览效果一致。
- 导入风格参考图后，参数能明显把照片推向该风格的观感方向（观感，非像素级复刻）。
- 全程无白屏/崩溃，所有失败场景有明确提示与重试路径。
